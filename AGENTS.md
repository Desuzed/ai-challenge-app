# Работа с GitHub через плагин Codex

Используйте этот порядок, когда нужно оформить pull request в GitHub.

1. Проверьте рабочую копию: `git status --short`, текущую ветку, `origin` и результаты нужных тестов.
2. Никогда не коммитьте изменения прямо в `main`. Создайте ветку с понятным именем, например `feat/token-accounting`.
3. Создайте локальный коммит после проверки тестов.
4. Для GitHub используйте подключённый GitHub-плагин Codex: сначала получите профиль и метаданные репозитория, убедитесь в правах на запись и узнайте ветку по умолчанию.
5. Создайте удалённую ветку от актуального `main` через плагин. Если `git push` не авторизован, не пытайтесь обходить авторизацию: перенесите изменённые файлы в эту ветку инструментами плагина (`create_file` для нового файла, `update_file` для существующего). Перед `update_file` получите текущий SHA файла через `fetch_file`.
6. Откройте PR через плагин с `base: main`, понятным заголовком и кратким описанием: что изменилось и какими командами это проверено.
7. Верните пользователю ссылку и номер PR. Не мержите PR, пока пользователь прямо не попросит об этом.

Для записи в GitHub пользователь должен явно попросить создать PR или отправить изменения. Не публикуйте ветки и PR самовольно.
