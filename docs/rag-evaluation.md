# Протокол оценки RAG

Этот файл использует тот же корпус и десять вопросов из
[`rag-control-questions.md`](rag-control-questions.md). Новые документы и
эмбеддинги для оценки не нужны: после изменений исходников пересоберите индекс
командой `go run ./cmd/indexdocs -root .`.

## Как получить сравнимый результат

Для каждого вопроса откройте чистую историю чата, выключите планировщик и
используйте одну модель. В журнале сохраните `ragTrace`, `ragSources` и ответ.

| Режим | Rewrite | Rerank | Порог | K до → после |
|---|---:|---:|---:|---:|
| A — baseline | нет | нет | -1.00 | 4 → 4 |
| B — фильтр | нет | нет | 0.35 | 8 → 3 |
| C — улучшенный | да | да | 0.35 | 8 → 3 |

## Таблица результатов

Поставьте 1, только если ответ содержит правильный факт **и** среди финальных
источников есть ожидаемый файл. Иначе поставьте 0. Отдельно запишите число
финальных источников: это позволяет увидеть, насколько фильтр уменьшил шум.

| № вопроса | A: балл / источники | B: балл / источники | C: балл / источники | Наблюдение |

Нормальный результат не обязан улучшить все десять строк: маленький корпус уже
сильно похож по тематике. Успех задания — прозрачное сравнение precision и
контроль ложного контекста, а не заранее обещанная цифра.

## Детерминированные тестовые данные

Автотест `internal/rag/search_test.go::TestSearchWithOptionsRewritesFiltersAndReranks`
создаёт временный мини-корпус из двух разделов: «История» и «Погода». Векторы
намеренно делают «Погоду» первым результатом первого этапа; rewritten-запрос
«Где история диалога?» содержит `agent history json`, поэтому reranker выводит
«Историю» на первое место. Это проверяет механику без сети, Ollama и LLM.
