# Инструменты MCP

## Подключение

Приложение использует официальный Go SDK Model Context Protocol. Сервер и клиент каждой интеграции соединяются через in-memory transport. Они выполняют handshake, `tools/list` и `tools/call`. Общий каталог передаёт агенту живые схемы и маршрутизирует вызовы. Отдельные HTTP-маршруты приложения показывают каталог и позволяют выполнить вызов для диагностики.

## Серверы и контекст проекта

Подключены пять MCP-серверов: локальный проект, Яндекс Диск, GitHub, погода и новости. Текущая локальная git-ветка получается вызовом `project_git_branch` сервера локального проекта. Сервер выполняет команду git в рабочем каталоге приложения и возвращает `branch`, `detached` и `commit`. `/diff` показывает этот результат пользователю без вызова языковой модели.

MCP-соединение и готовность внешнего сервиса — разные состояния: список инструментов может работать без OAuth-токена, а операция внешней записи — нет.

## Локальный проект

`project_git_branch` принимает пустой объект и читает текущую локальную git-ветку рабочего каталога сервера. Результат содержит `branch`, `detached`, опционально `commit`. При detached HEAD ветка пуста, detached равен true и возвращается commit. Для новой ветки без коммитов branch доступен, commit может отсутствовать.

Команды git и путь фиксированы сервером; модель не выбирает произвольную команду или каталог. Этот инструмент только читает состояние. `/diff` вызывает его напрямую через MCP и выводит фактическую ветку. `/help` и `/structure` не вызывают git-инструмент. На паузе задачи `/diff` не вызывает MCP и сообщает об этом. Default branch GitHub и ветка диалога не заменяют текущую локальную ветку.

## GitHub

| Инструмент | Назначение |
|---|---|
| `github_get_repository` | Имя, описание, default branch, приватность и URL |
| `github_list_files` | Файлы и каталоги выбранного ref |
| `github_get_file` | Чтение UTF-8 файла |
| `github_list_issues` | Список issues |
| `github_put_file` | Создание/обновление файла отдельным коммитом |
| `github_delete_file` | Удаление файла отдельным коммитом |

Репозиторий задаёт `GITHUB_REPOSITORY`; для приватного доступа и записи нужен `GITHUB_TOKEN`. Эти инструменты работают через GitHub REST API, поэтому не видят незакоммиченные изменения локальной рабочей копии.

Запись инструментом выполняется при вызове. Дополнительного универсального подтверждения внутри bridge нет; агент должен вызывать запись только по запросу пользователя. Наличие схемы в каталоге не является основанием записывать данные. `/help` не передаёт модели инструменты записи.

## Яндекс Диск

`list_desktop_videos` ищет видео в `VIDEO_SOURCE_DIR` или `~/Desktop`. `analyze_desktop_video` использует `ffprobe` для метаданных. `estimate_video_upload` показывает размер, квоту и влияние на токены. `upload_video_to_yandex` потоково отправляет выбранное видео в существующую подпапку `YANDEX_DISK_ROOT`.

Совместимое имя аргумента папки в API — `lessonFolder`; это имя поля существующего инструмента. Видеобайты не передаются LLM: модель получает схемы, аргументы и текстовые результаты. Для внешней загрузки требуется OAuth-токен. Имя файла сверяется со списком доступных видео; нельзя подставить произвольный путь.

## Погода и новости

Погодный сервер сохраняет наблюдения Москвы в JSON. Начальный период — одна минута; сохранённое расписание может заменить его. `collect_weather`, `weather_latest`, `weather_history`, `weather_summary` работают с наблюдениями; `get_city_weather` получает погоду другого города без изменения истории Москвы. `scheduler_status`, `set_weather_schedule`, `stop_weather_scheduler` управляют сбором. `clear_weather_history` удаляет наблюдения.

`search_news` получает сырые статьи Google News RSS по городу, теме, датам и лимиту. Агент формирует сводку по результатам. Сохранение сводки в GitHub — отдельное действие пользователя; получение новостей само по себе не означает публикацию.

## Проверка и источники

`GET /api/mcp/tools` возвращает каталог серверов и схемы. `POST /api/mcp/call` принимает `name` и `arguments`. Успешные вызовы в чате отражаются в `toolExecutions`; источники отмечаются `MCP:<имя инструмента>`. Ошибка инструмента не служит доказательством выполненной операции.

Независимый тест MCP проверяет протокол и временный репозиторий. Живая проверка внешнего GitHub, Диска или новостей требует отдельного доступа к соответствующему сервису. Локальный Project MCP работает без этих внешних токенов.
