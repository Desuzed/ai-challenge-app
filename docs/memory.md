# Память и контекст

## История и стратегии

История диалога между перезапусками хранится в `.local/agent-history.json`; путь можно заменить настройкой `AGENT_HISTORY_FILE`. Полный архив и контекст текущего вызова — разные данные. Окно не удаляет раннюю переписку из архива.

Sliding Window отправляет последние N user/assistant сообщений. N — число сообщений, а не обменов; допустимы 2–40, начальное значение нового чата — 32. Facts добавляет sticky facts отдельно от окна. Branching использует активную ветку диалога; контрольная точка позволяет создавать независимые продолжения.

## Явные слои памяти

Короткая память определяется перепиской. Рабочая и долговременная память записываются явными командами интерфейса/API; модель не получает право произвольно сохранять любую догадку. Профили задают роль, стиль, формат и ограничения ответа. Выбор профиля хранится для сессии; долговременные записи привязаны к пользователю.

TaskMemory хранит исходную цель, уточнения, ограничения, термины, пользовательские цитаты и номера ходов отдельно от planner TaskState. Явные условия сохраняются, даже если исходная реплика вышла за окно истории.

```text
Цель: подготовить инструкцию запуска.
Уточнение: Ollama уже запущена.
Ограничения: без Docker; до трёх действий.
Термин: ключ = DEEPSEEK_API_KEY.
```

Поля задаются с новой строки. `Ограничения:` заменяет предыдущий список, поэтому при изменении условия повторяйте остальные актуальные условия. `Отменить ограничение:` удаляет совпавшее ограничение. Повторный термин с тем же именем заменяет значение. Если явной цели нет, исходная реплика служит буквальным fallback.

Текущие пользовательские уточнения имеют приоритет над противоречащими старым условиям профиля и истории. Глобальные, task и state invariants остаются обязательными. Пользовательская память подтверждает пожелания пользователя; факты о приложении подтверждаются документацией или результатами MCP.

## Планировщик

Planner выключен по умолчанию для нового чата. При включении он формирует текстовую спецификацию, открытые вопросы, решения и следующие шаги. Этапы и переходы контролирует сервер. Подтверждение плана, завершение реализации и прохождение проверки — разные явные действия.

Пауза не меняет текущий этап. Пока задача приостановлена, модель и инструменты не запускаются. Возобновление продолжает сохранённое состояние. Возврат к доработке инвалидирует подтверждения последующих этапов.

## Очистка и помощь

Очистка переписки сбрасывает историю текущего диалога и TaskMemory; пользовательские долговременные записи и выбранные параметры чата сохраняются. В Branching память восстанавливается вместе с соответствующим контекстом.

`/help <вопрос>` и `/structure` обрабатываются как отдельные команды внутри общего чата. Сохраняемого режима помощи и предыдущей темы нет: каждый вызов содержит свой вопрос. Вопрос помощи не меняет TaskMemory и не продвигает planner. Профиль, модель и правила пользователя сохраняются; контекст помощи сфокусирован на текущем вопросе. Ответ остаётся в общей истории, а следующее обычное сообщение идёт в обычный чат. Текущая git-ветка запрашивается отдельно через `/diff`; эта команда не меняет TaskMemory, planner и ветку беседы.
