# Демонстрация цитат и отказа RAG

Индексатор использует подготовленный список исходников из `ragindex.DefaultFiles`. Каждый фрагмент хранит путь к файлу, раздел, `chunk_id`, текст и эмбеддинг. Если вы изменили индексируемый файл, пересоберите индекс:

```sh
go run ./cmd/indexdocs -root .
```

Затем перезапустите Go-сервер приложения, чтобы он прочитал обновлённые исходники и индекс. Убедитесь, что Ollama запущена и модель `embeddinggemma` доступна. Включите **Поиск по документам (RAG)** и задайте любой вопрос из [контрольного набора](rag-control-questions.md). Ответ показывает нумерованные утверждения, источники, разделы, ID фрагментов и точные цитаты. В журнале запроса также доступны `ragSources`, `ragTrace`, `ragAbstained`, `ragReason` и `ragModelCallSkipped`.

Чтобы проверить отказ при высоком пороге, установите **Порог similarity** в `1.0` и задайте посторонний вопрос, например: «Какой сегодня курс евро к иене?». Если ни один чанк не достиг порога, сервер ответит «Не знаю», попросит уточнить вопрос, вернёт `ragSources: []` и `ragModelCallSkipped: true`. Ответная модель для этого отказа не вызывается. После демонстрации верните обычный порог `0.35`.

Десять живых вопросов можно прогнать через локальный Ollama retrieval и DeepSeek completion:

```sh
go run ./cmd/evaluaterag -root .
```

Ключ DeepSeek читается из переменной окружения `DEEPSEEK_API_KEY` или `.env`; программа его не печатает. Результаты записываются после каждого вопроса в `.local/rag-eval/results.json` и `.local/rag-eval/results.md`. Флаг `-resume` продолжает только при совпадении отпечатка индекса, модели и набора вопросов; после изменения индекса или вопросов начнётся новый прогон.

Отчёт независимо проверяет ожидаемый файл и наличие каждой точной цитаты в тексте указанного чанка. Проверка ключевых слов — только смысловой proxy: она не доказывает, что цитата поддерживает утверждение. Для этого оставлена отдельная ручная оценка.

Если retrieval не нашёл чанков выше порога, сервер возвращает отказ с пустым списком источников без вызова модели. Если модель вернула неверный `chunk_id` или цитату, отсутствующую в указанном чанке, сервер удаляет утверждение. Если проверяемых утверждений не осталось, пользователь также получает отказ. Совпадение текста цитаты гарантирует её точность, но не доказывает смысловую связь цитаты с утверждением.
