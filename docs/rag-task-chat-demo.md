# Чат с RAG и памятью: сценарии для видео

Чат отвечает по локальной базе **этого проекта**. Для записи берите вопросы
про запуск приложения и его RAG, историю и память: сведения о путешествиях,
товарах или текущих новостях в эту базу не входят.

## Подготовка записи

1. Запустите Ollama с уже установленной моделью `embeddinggemma`.
2. Индекс уже обновлён в рамках задания. После новых изменений исходников
   пересоберите его в папке проекта: `go run ./cmd/indexdocs -root .`.
3. Запустите приложение: `go run .`, откройте <http://localhost:8080>.
4. В существующем чате включите **«Поиск по документам (RAG)»**. Для нового
   сценария начните с пустой истории. Все прежние параметры находятся в
   **«Параметрах»** и действуют на этот же чат.
5. Для обычной записи можно использовать **Sliding Window, N = 32**: этого
   достаточно для 15 обменов вопросами и ответами. Для наглядной проверки
   памяти уменьшите N до **4 сообщений**. В существующем браузерном чате
   прежнее N сохраняется: при необходимости измените его в «Параметрах».
   Вся история продолжает храниться,
   а память задачи передаётся отдельно от окна.

Для каждого сценария отправляйте пункты ниже **последовательно в одном чате**.
Между сценариями очистите историю чата. На 10–15-м вопросе не повторяйте
исходные условия: так демонстрация действительно проверяет память.

Планировщик продолжает работать по своему переключателю: при включении он
формирует ТЗ и ведёт этапы. Для этих вопросов о документации выберите обычные
ответы, отключив планировщик **сами в дашборде плана**, если он был включён.
Для проверки совместимости затем включите его снова и проверьте этапы и паузу.
Остальные параметры сохраняют выбранные вами значения.

## Как фиксировать память

Чтобы запись была воспроизводимой, используйте понятные явные формулировки:

- `Цель:` — цель текущей задачи;
- `Уточнение:` — подтверждённые пользователем сведения;
- `Ограничения:` — полный актуальный список ограничений, разделённых `;`;
- `Термин: название = значение` — согласованное значение термина;
- `Отменить ограничение: текст` — убрать указанное ограничение.

Каждое поле пишите с новой строки, а его значение — в той же строке после
двоеточия. Несколько ограничений внутри одного поля разделяйте `;`.

Новое сообщение `Ограничения:` **заменяет** прежний список целиком. Поэтому
при изменении одного условия повторите остальные актуальные ограничения.
Память пользователя показывает его намерения и условия; источники документации
подтверждают факты о приложении. Факт, что пользователь назвал macOS, не нужно
выдавать за сведения из README.

## Сценарий 1: безопасный локальный запуск — 15 сообщений

**1.** Отправьте это одним сообщением:

```text
Цель: подготовить инструкцию безопасного локального запуска AI Challenge App.
Уточнение: я новичок и работаю на macOS.
Ограничения: без Docker; без облачного развёртывания; до 5 действий в итоговой инструкции.
Термин: ключ = DEEPSEEK_API_KEY.
Какая версия Go нужна для запуска?
```

**2.** Как подготовить локальный файл .env из шаблона?

**3.** Куда записать ключ, чтобы он не оказался в браузере?

**4.** Если ключ одновременно задан в окружении процесса и в .env, какой из них используется?

**5.** В каком заголовке сервер отправляет ключ DeepSeek?

**6.** Как запустить приложение и по какому адресу открыть чат?

**7.** Какой HTTP-маршрут принимает сообщения основного чата?

**8.** Отправьте это одним сообщением:

```text
Ограничения: без Docker; без облачного развёртывания; до 3 действий в итоговой инструкции.
Уточнение: Ollama уже установлена и запущена.
Какую локальную модель эмбеддингов использует поиск?
```

**9.** В каком файле сохраняется история диалогов между перезапусками?

**10.** Почему короткое окно сообщений не должно удалять сохранённую историю чата?

**11.** Какие документы индексируются и почему файл .env не должен входить в базу?

**12.** Что делать, если после изменения исходников поиск сообщает об устаревшем индексе?

**13.** Как проверить, что к ответу приложены настоящий файл, раздел и точная цитата?

**14.** Напомни мою цель, платформу, значение слова «ключ» и актуальный лимит действий. Отдельно объясни по документации, где хранится история.

**15.** Собери итоговую инструкцию для моей задачи с учётом всех уточнений. Соблюди актуальный лимит действий и приложи источники.

### Что показать зрителю

- После сообщения 8 лимит меняется с **5** на **3**, а остальные ограничения остаются.
- В сообщениях 14–15 сохраняются цель, macOS, отсутствие Docker и облачного
  развёртывания, уже установленная Ollama и значение слова «ключ».
- Панель памяти показывает актуальное состояние; раннее сообщение уже не
  входит в окно 4 сообщений, но остаётся в полной истории.
- Ответы о приложении содержат файл, раздел, ID фрагмента и цитату.
- После обновления страницы история и память остаются.

## Сценарий 2: объяснение RAG и памяти — 15 сообщений

**1.** Отправьте это одним сообщением:

```text
Цель: объяснить архитектуру чата с RAG и памятью задачи для учебного видео.
Уточнение: слушатель понимает HTTP, но впервые знакомится с RAG.
Ограничения: без смены модели; без внешних векторных сервисов; краткий итоговый ответ.
Термин: память задачи = отдельно сохранённые цель, уточнения, ограничения и термины пользователя.
Какие этапы проходит новый вопрос в чате с включённым RAG?
```

**2.** Чем сохранённая история отличается от сообщений, отправляемых модели в текущем запросе?

**3.** Какие две стратегии разбиения документов есть в индексаторе?

**4.** Какой размер фиксированных фрагментов и их перекрытие?

**5.** Какие метаданные позволяют показать источник найденного фрагмента?

**6.** Сколько кандидатов берётся до фильтрации и сколько фрагментов остаётся по умолчанию?

**7.** Для чего нужны порог similarity, rewrite и reranking?

**8.** Отправьте это одним сообщением:

```text
Уточнение: мне нужна демонстрация памяти с окном 4 сообщения.
Ограничения: без смены модели; без внешних векторных сервисов; подробный итоговый ответ.
Как память задачи помогает после того, как раннее сообщение вышло за окно?
```

**9.** Как выбранные профиль, стратегия контекста и память пользователя учитываются вместе с найденными документами?

**10.** Как контекст задачи помогает искать документы для короткого уточняющего вопроса?

**11.** Если подходящего фрагмента не найдено, что должен ответить ассистент и что покажет блок источников?

**12.** Что произойдёт, если модель вернёт выдуманный chunk_id или цитату, отсутствующую в документе?

**13.** Гарантирует ли дословное совпадение цитаты, что она по смыслу доказывает утверждение?

**14.** Вспомни мою цель, аудиторию, согласованное значение «память задачи» и актуальные ограничения. Затем объясни по документации, как сохраняется история.

**15.** Подготовь итоговое объяснение для моего видео: путь вопроса, поиск, память, проверка цитат и сохранение истории. Учти актуальную просьбу о подробном ответе и приложи источники.

### Что показать зрителю

- На 8-м сообщении **краткий** итог заменяется **подробным**; запреты на смену
  модели и внешние векторные сервисы сохраняются.
- В конце ассистент помнит аудиторию, цель, определение термина и окно 4 сообщений.
- RAG выполняется на каждом ходе, включая сообщения с уточнениями.
- Предыдущие ответы не используются как новые документальные доказательства:
  цитаты проверяются по фрагментам, найденным для текущего вопроса.

## Дополнительный показ честного отказа

После основного сценария можно задать: «Какой сегодня курс евро к иене?».
Таких данных в локальной базе нет. Ожидается честное сообщение об отсутствии
подтверждения и пустые документальные источники, а не придуманная ссылка.
Даже если поиск вернул похожие фрагменты, ответная модель должна отказаться
при отсутствии ответа в них. Такой отказ проверяется отдельно от ситуации,
когда поиск вообще не нашёл контекста и вызов ответной модели пропущен.

## Совместимость с предыдущими заданиями

| Настройка | Поведение общего чата |
|---|---|
| Sliding Window | В модель попадают последние N реплик; полная история сохраняется |
| Полная история | Сохраняется целиком независимо от размера окна |
| Память задачи | Отдельно передаётся модели; не удаляется вместе с ранними репликами из окна |
| Планировщик, этапы и пауза | Управляются прежними кнопками; включение RAG их не отключает |
| Профили, Sticky Facts, глобальная и рабочая память | Участвуют в формировании контекста вместе с памятью задачи |
| MCP-инструменты предыдущих заданий | Сохраняют существующую доступность; данные инструмента не выдают за цитату документа |
| Переключатель RAG и настройки reranking | Управляют поиском этого же чата |
| Значение N по умолчанию | 32 для новых сессий; прежний сохранённый выбор не меняется автоматически |
| Очистка истории | Начинает новый диалог и сбрасывает память его задачи |

При `N = 4` ранняя цель находится в отдельной памяти, и это видно в журнале
`requestMessages`. При `N = 32` дополнительно остаётся весь короткий сценарий.
Увеличение окна само по себе не заменяет память цели и актуальных ограничений.

## Проверка результата

Минимальный критерий для каждого основного сценария: 15 пользовательских
сообщений, 30 сохранённых реплик, цель и изменённые ограничения в финальной
памяти, источник с проверяемой цитатой для подтверждённых фактов, сохранение
истории после перезагрузки. Честный отказ не считается ответом с найденным
источником: он отдельно показывает отсутствие доказательств.

Дословность цитаты проверяется автоматически. Смысловую поддержку утверждения
цитатой и соблюдение пожеланий в финальном тексте нужно оценивать по содержанию,
а не только по числу источников.
