# Проверка работы

## Автоматические проверки

```sh
go test ./...
go vet ./...
node --check static/app.js
git diff --check
```

Тесты индексатора проверяют границы чанков, метаданные, cache и загрузку корпуса. Тесты поиска проверяют retrieval, freshness, rewrite, фильтрацию и rerank. Тесты агента проверяют память, историю, цитаты, инструменты и planner. Project MCP проверяется на временном настоящем git-репозитории с переключением ветки и detached HEAD.

HTTP-тестам может требоваться временный localhost-порт. Отказ среды разрешить порт не доказывает дефект MCP. Ответы тестовой LLM и тестовые эмбеддинги не являются результатами живой модели.

## Пересборка и живой RAG

Запустите Ollama с `embeddinggemma`, затем:

```sh
go run ./cmd/indexdocs -root .
go run ./cmd/evaluaterag -root .
```

`evaluaterag` делает десять реальных запросов через Ollama retrieval и DeepSeek completion. Ключ читает из окружения или `.env`. После каждого вопроса результаты сохраняются в `.local/rag-eval/results.json` и `results.md`. `-resume` использует ответы только при совпадении индекса, модели и набора вопросов.

Оценка отдельно проверяет ожидаемый файл и точность цитат. Semantic proxy — совпадение ключевых слов, а не доказательство правильного смысла. Итоговую смысловую поддержку утверждений оценивайте вручную.

## Проверка /help и MCP

Запустите приложение с отдельными файлами состояния для проверки. Выполните автоматическую HTTP-проверку:

```sh
python3 scripts/check_project_help.py --app http://127.0.0.1:18081
```

По умолчанию используется локальная модель `ollama/qwen3:4b`; вопросы и документы остаются на компьютере. Скрипт выполняет настоящий `/reindex`, проверяет инструкцию `/help`, затем в одной тестовой сессии задаёт вопросы через `/help <вопрос>` и `/structure`. Проверяются точные цитаты, полнота ответа, отказ без сведений, неизвестная команда и обычный чат после команд помощи. Помощь должна запускаться только явно, без сохранённого режима. Результаты записываются в `.local/project-check/help-results.json`. Перед запуском сервера задайте `PORT=18081`, `AGENT_HISTORY_FILE=.local/project-check/agent-history.json` и `WEATHER_DATA_FILE=.local/project-check/weather.json`, чтобы проверка использовала отдельные данные. Для явно выбранного облачного провайдера доступен `--model deepseek-flash`; это передаёт вопросы и найденную документацию DeepSeek.

Для ручной проверки отправьте `/help`: команда показывает инструкцию без генерации. Затем задайте через `/help <вопрос>` вопросы о каталогах `internal`, `cmd`, `static`, о MCP и о хранении истории. В ответах должны быть корректные факты, пути и точные цитаты. В `/help` и `/structure` не должно быть строки текущей git-ветки и вызовов MCP. Отдельно отправьте `/diff`: среди источников должен быть `MCP:project_git_branch`, показанная ветка должна совпадать с `git branch --show-current`, а вызов модели — пропускаться. После команды отправьте обычное сообщение с выключенным RAG: оно должно идти в обычный чат, без обязательного поиска документации и вызова `project_git_branch`. Перезапуск со старым состоянием помощи должен сохранять историю и настройки, но не включать помощь для обычных сообщений.

Проверьте `/help <вопрос>` при выключенном переключателе RAG: поиск должен остаться включённым для команды. Проверьте вопрос без сведений в корпусе: ассистент должен сообщить об отсутствии документального ответа. Затем измените индексируемый файл и убедитесь в ошибке устаревшего индекса; пересоберите его.

`GET /api/mcp/tools` должен показать Project MCP и `project_git_branch` с признаком чтения. Вызов `POST /api/mcp/call` с пустыми аргументами должен вернуть текущую ветку. Detached HEAD проверяйте на временном репозитории; не меняйте рабочую копию только ради теста.

## Длинный диалог

Проверьте `/help расскажи о проекте` с `maxTokens: 512` и выключенным RAG-переключателем: должны прийти проверенный факт из README и источник, без текущей git-ветки и вызова MCP. Тест провайдера с немедленными HTTP 200-заголовками и задержанным телом должен дать таймаут, а не общую ошибку 502. Во время ожидания браузер показывает секунды; после ошибки восстанавливает кнопку отправки и сохраняет текст ошибки в журнале.

`go run ./cmd/evaluateragchat -root . -window 4` проверяет два последовательных сценария по 15 пользовательских ходов с настоящими Ollama и DeepSeek. Отдельный state-файл и отчёты сохраняются в `.local/rag-chat-eval`. Ранние условия должны оставаться в TaskMemory, хотя они уже вышли из окна. Этот прогон длиннее минимальной проверки помощи и выполняется, когда меняются память или контекст.

## Параметры локальной модели

```sh
python3 scripts/check_local_llm.py --check
python3 scripts/benchmark_local_settings.py --help
```

A/B runner использует набор из `scripts/fixtures/local-model-cases.json`, чистые сессии, прогрев и чередование конфигураций. Сравнивайте правильность, формат, finish reason, токены, время и память. Старые измерения другой конфигурации не заменяют новый прогон.
