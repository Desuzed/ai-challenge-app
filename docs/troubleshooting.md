# Диагностика

## Индекс отсутствует или устарел

В работающем чате выполните `/reindex` и дождитесь отчёта. Для запуска из терминала подготовьте локальную Ollama с `embeddinggemma` и выполните `go run ./cmd/indexdocs -root .`. Убедитесь, что приложение запущено из того же корня и читает `.local/rag/index-structure.json`. После изменений документов и индексируемых исходников пересоберите индекс; новые файлы требуют того же действия.

Если эмбеддинг не получен, проверьте доступность `OLLAMA_URL` и наличие модели. Индексатор не заменяет недоступный сервис фиктивными векторами. Совместимость размера вектора вопроса и индекса также обязательна.

## Нет документального ответа

Посмотрите `ragTrace`: исходный вопрос, rewrite, vector/lexical candidates, фильтрацию и финальные источники. Слишком узкий вопрос или порог может убрать полезные фрагменты; lexical-канал может сохранить их по точным терминам. Высокий cosine-порог сам по себе не гарантирует пустую выдачу.

Задайте вопрос в одной команде: `/help <вопрос>`. `/help` без вопроса показывает инструкцию и не меняет обработку следующих сообщений. Для готового вопроса о структуре используйте `/structure`. Неизвестная slash-команда не запускает модель.

`retrieval_empty` означает отсутствие финальных фрагментов. `model_no_claims` — модель не дала утверждений при имеющемся контексте. `invalid_evidence` — источник или цитата не прошли проверку. `invalid_structured_output` и `structured_output_truncated` относятся к формату ответа. MCP-источник команды `/diff` подтверждает текущую git-ветку. Ответы `/help` и `/structure` используют только документальные источники.

## Модель не завершила ответ

Проверьте finish reason и фактический бюджет. Обрыв по лимиту может оставить неполный JSON. Внутренние рассуждения локальной модели также расходуют бюджет. Увеличьте лимит/окно в поддерживаемых пределах или сократите вопрос и историю. Контекст вместе с резервом ответа должен помещаться в выбранное окно.

Если удалённая Ollama недоступна, проверьте URL, сеть и каталог моделей. Пустой каталог и ошибка подключения — разные состояния. Не подменяйте удалённую модель локальной без выбора пользователя.

## Project MCP не читает ветку

Убедитесь, что сервер запущен внутри нужного git-репозитория и git доступен процессу. Сравните прямой `git branch --show-current` с `/api/mcp/call`. При detached HEAD имя ветки пустое; это нормальное состояние с указанием commit, а не default branch удалённого репозитория.

## Внешняя интеграция не выполняет действие

Подключённый MCP-каталог не подтверждает наличие OAuth-токена, права записи или доступность сети. Для GitHub проверьте репозиторий и права токена, для Диска — OAuth и папку, для видеоанализа — `ffprobe`. Не сообщайте об успешной записи без успешного результата инструмента.

## История и интерфейс

Небольшой `maxTokens` ограничивает длину генерации, но не время ожидания провайдера. DeepSeek может отправить HTTP-заголовки до готовности JSON-тела. Основной чат ограничивает весь запрос 60 секундами; таймаут тела распознаётся как HTTP 504. Для HTTP-ошибки самого DeepSeek показывается код провайдера. В журнале браузера есть `error` и `elapsedMs`; отсутствие RAG-полей в ошибке не означает, что поиск был выключен.

Проверьте `/help расскажи о проекте`: он должен использовать вводные фрагменты README. Конкретный вопрос о неописанной теме по-прежнему должен завершаться отказом без выдуманных сведений. Если DeepSeek регулярно превышает лимит ожидания, повторите запрос позже или явно выберите другую доступную модель.

Проверьте cookie сессии и доступность файла состояния. Изменение N сохраняется отдельным PATCH, без отправки вопроса модели. Если старая история не появилась, сначала уточните, совпадает ли сессия; не удаляйте файл истории как способ диагностики.

Ключи и сырые личные данные не вставляйте в публичные отчёты. Для воспроизведения используйте отдельный state-файл и новые сессии.
