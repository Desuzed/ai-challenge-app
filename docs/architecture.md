# Архитектура

## Структура каталогов

Каталог `internal/` содержит реализацию backend: агент, HTTP-обработчики, модели данных, клиенты языковых моделей, RAG и MCP. Каталог `cmd/` содержит команды индексации и оценки RAG. Каталог `static/` содержит HTML, CSS и JavaScript браузерного интерфейса. Файл `main.go` соединяет эти компоненты и запускает HTTP-сервер. Каталоги `docs/` и `scripts/` содержат документацию и диагностические скрипты соответственно.

## Компоненты

Браузер в `static` отправляет JSON локальному Go backend. `internal/handlers` проверяет запрос и определяет пользователя и сессию. `internal/agent` владеет историей, настройками, памятью, планировщиком и проверкой ответа. `internal/llmrouter` направляет запрос к выбранному провайдеру. `internal/models` описывает общие данные.

RAG состоит из индексатора `internal/ragindex` и поискового слоя `internal/rag`. Индексатор работает отдельной командой; агент читает подготовленный структурный индекс при запросе. MCP-каталог `internal/mcpbridge` объединяет независимые серверы инструментов. Подключения собираются в `main.go`.

## Основной запрос

1. Браузер отправляет `POST /api/agent/chat` с сообщением, моделью, стратегией, параметрами генерации и RAG.
2. Агент выбирает сессию и обновляет явную память задачи из пользовательской реплики.
3. При включённом RAG поиск выбирает фрагменты по текущему вопросу.
4. Стратегия контекста собирает историю и добавляет профиль, память и обязательные правила.
5. Для инструментального запроса агент получает живые MCP-схемы и результаты вызовов.
6. Выбранная модель генерирует ответ. Документальные утверждения проходят проверку цитат.
7. Агент сохраняет историю и возвращает ответ, источники, состояние и метрики.

## Режим помощи разработчику

Команды обрабатываются до поиска и вызова модели. `/help` показывает инструкцию без генерации. `/help <вопрос>` отвечает только на вопрос в этой команде; `/structure` — готовый запрос о структуре. Помощь не меняет обработку последующих обычных сообщений и не сохраняет режим в сессии. Неизвестные команды возвращают сообщение о доступных командах без генерации.

Для команд помощи обязательный поиск выбирает текстовую документацию; Go-чанки исключаются до ранжирования. `/help` и `/structure` не вызывают Git MCP и не добавляют ветку к ответам. `/diff` отдельно читает текущую ветку через `project_git_branch` и выводит результат без поиска документов и генерации. Контекст модели содержит текущий вопрос и выбранные системные правила, профиль и память; старые отказы и нерелевантные диалоги исключаются. Это не меняет архив общей переписки.

Помощь не обновляет TaskMemory и не продвигает planner. При паузе задачи генерация не выполняется; `/diff` также пропускает вызов git-инструмента. Ошибки индекса, формата ответа и проверки цитат различаются. Не прошедший проверку ответ можно сгенерировать повторно один раз; расход обеих попыток учитывается.

`/reindex` вызывает серверный `ragindex.Rebuilder` напрямую и не обращается к генеративной модели. Индексатор перечитывает весь корпус, переиспользует векторы неизменившегося текста и сохраняет полные JSON-файлы через атомарную замену каждого файла. Если эмбеддинги не построены, сохранение новых индексов не начинается. Контрольная команда переиндексации не продвигает этап задачи.


## Границы данных

Полная история и состояние хранятся локально в JSON. Контекст модели — только выбранная часть истории плюс отдельные блоки инструкций, памяти, документов и результатов MCP. Найденные фрагменты не превращаются в пользовательскую память. Ответ может содержать цитаты, которые остаются в сохранённой переписке.

Ветка диалога Branching, текущая локальная git-ветка и default branch GitHub — три разных понятия. Branching управляет контекстом беседы; Project MCP — рабочей копией; GitHub MCP — удалённым репозиторием.

## Ограничения текущей системы

Это локальное приложение без производственной многопользовательской авторизации. Cookie выделяют состояния пользователя и сессии. Нет автономного исполнителя разработки, изоляции выполнения произвольного кода или деплоя. Планировщик ведёт текстовое состояние задачи, а не доказывает, что реализация и тестирование продукта выполнены.
