# Локальная диагностика RAG retrieval

Проверен вопрос «Где сохраняются два индекса и отчёт?» на `.local/rag/index-structure.json` с локальной Ollama и `embeddinggemma`. Индекс прошёл встроенную проверку SHA-256 исходников. DeepSeek и генерация ответа в диагностике не использовались. Порог оставался `0.35`.

До исправления tokenizer переписывал запрос в `сохраняются два индекса отч`: буква `ё` считалась разделителем, поэтому `отчёт` обрезался до `отч`. В режиме 8→3 с rewrite и rerank оба релевантных чанка набирали cosine `0.341380` и `0.336197`, поэтому retrieval возвращал ноль matches.

После перехода на Unicode-распознавание букв и цифр переписанный запрос стал `сохраняются два индекса отчёт`. В режиме 8→3 с rewrite и rerank чанк `README.md`, раздел `AI Challenge App / Индексация документов`, `chunk_id=b0a692349b3619a1c60febac` получил cosine `0.371183`, lexical `0.500000`, rerank `0.396947` и прошёл порог. Второй README чанк `15d4f194be95378c46640c23` получил cosine `0.347921` и остался ниже порога. При выключенном rerank результаты совпали по cosine и составу matches.

Для сравнения, без rewrite в режиме 8→3 первый README чанк `15d4f194be95378c46640c23` получил cosine `0.398815`, а второй `b0a692349b3619a1c60febac` — `0.390081`; оба прошли порог. При rerank они получили соответственно lexical/rerank `0.750000 / 0.469052` и `0.500000 / 0.412065`. Таким образом, исправление устранило обрезание слова и вернуло один релевантный чанк в дефолтной конфигурации. Эвристический rewrite по-прежнему может снизить полноту по сравнению с исходным вопросом; reranker отфильтрованные чанки не восстанавливает.

Полный вывод локального прогона сохранён в `.local/ragdiag-after.txt` для проверки кандидатов, оценок и текста. Временная команда `cmd/ragdiag` после измерения удалена.
