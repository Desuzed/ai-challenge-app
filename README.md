# AI Challenge App

Минимальное full-stack приложение на Go: браузер отправляет вопрос локальному серверу, сервер вызывает DeepSeek API и возвращает текстовый ответ. Frontend написан на обычных HTML, CSS и JavaScript, поэтому проект легко показать и объяснить на видео.

## Что происходит

```text
Браузер → POST /api/chat → Go backend → DeepSeek API
Браузер ← JSON с ответом ← Go backend ← DeepSeek API
```

API-ключ не попадает в браузер: при запуске сервер сначала использует непустое значение `DEEPSEEK_API_KEY` из окружения процесса, а если его нет — значение из локального файла `.env`. Ключ передаётся DeepSeek только в HTTP-заголовке `Authorization`.

## Быстрый запуск

Требуется Go 1.21 или новее.

1. Откройте Terminal и перейдите в папку проекта:

   ```bash
   cd /Users/artemiy/Ai_projects/ai-challenge-app
   ```

2. Создайте локальный файл конфигурации — Git его игнорирует:

   ```bash
   cp .env.example .env
   chmod 600 .env
   ```

3. Откройте `.env` локальным редактором и вставьте ключ после `=`:

   ```text
   DEEPSEEK_API_KEY=вставьте_ваш_ключ_сюда
   ```

4. Запустите приложение в том же окне Terminal:

   ```bash
   go run .
   ```

5. Откройте [http://localhost:8080](http://localhost:8080), задайте вопрос и нажмите кнопку.

Чтобы остановить сервер, нажмите `Ctrl+C` в Terminal. Для временной подмены ключа можно задать `DEEPSEEK_API_KEY` в окружении перед запуском: его непустое значение имеет приоритет над `.env`. Для другого порта перед запуском выполните `export PORT=8090`.

> Файл ключа — `.env` в корне проекта. Его имя зафиксировано в константе `localEnvFile` в [main.go](main.go), а имя строки с ключом — в `apiKeyEnvVar` того же файла. `.env.example` — безопасный шаблон; `.env` исключён из Git и содержит только локальный секрет.

## Структура

- `main.go` — HTTP-сервер, маршруты, чтение локального API-ключа и базовые защитные заголовки.
- `internal/deepseek/client.go` — Go HTTP-клиент и запрос к DeepSeek.
- `internal/handlers/handlers.go` — проверка входного JSON и понятные ошибки.
- `internal/models/models.go` — формы JSON-запросов и ответов.
- `static/` — страница, стили и JavaScript для отправки вопроса.
- `*_test.go` — автоматические тесты backend-логики.

## Сценарии сравнения ответа

Введите вопрос на странице и используйте его без изменений во всех запусках: так проще сравнить влияние режимов. Переключайте радиокнопки по порядку и делайте по 2–3 запуска в каждом режиме при одинаковых `temperature` или `top_p`.

1. **Без ограничений** — обычный свободный ответ; контроль формата, смысловой длины и окончания отсутствует.
2. **Только формат** — API получает `response_format: {"type":"json_object"}` и инструкцию вернуть только JSON с полями `film`, `actors` и `answer`.
3. **Только длина** — инструкция ограничивает ответ 300 символами, а сервер передаёт `max_tokens: 120`.
4. **Только завершение** — модель получает инструкцию закончить ответ и скрытую стоп-последовательность; она не попадает в видимый ответ.
5. **Все ограничения** — JSON, поле `answer` до 220 символов, инструкция завершить ответ, скрытая стоп-последовательность и лимит `max_tokens: 180`.

В техническом журнале видно выбранный режим, фактический лимит токенов, причину остановки (`finishReason`), переданную стоп-последовательность (`stopSequence`), длительность, число символов и текст, который сервер вернул из модели. Стоп-последовательность видна только в технической сводке, но отсутствует в ответе модели. API-ключ в журнал не попадает.

Страница отправляет `{"prompt":"...","mode":"...","settings":{...}}` на `/api/chat`. Сервер добавляет инструкцию соответствующего режима, вызывает `deepseek-v4-flash` через `https://api.deepseek.com/chat/completions` и возвращает `{"answer":"..."}`.

## Настройки и технический журнал

На странице есть переключатель между двумя режимами сэмплирования и ползунки, которые сразу показывают выбранное значение:

- `temperature` от 0 до 2 — чем выше, тем свободнее и разнообразнее ответ;
- `top_p` от 0 до 1 — выбор из наиболее вероятного «ядра» вариантов;
- `max_tokens` — максимальная длина ответа.

`temperature` и `top_p` не включаются одновременно: DeepSeek рекомендует изменять один из них. `top_k` и `seed` отсутствуют в текущей спецификации Chat Completions, а `frequency_penalty` и `presence_penalty` устарели и не работают — поэтому интерфейс объясняет это, но не отправляет их в API.

Блок «Технический журнал» показывает JSON, который браузер отправил backend, и безопасную сводку ответа: модель, настройки, HTTP-статус, длительность и число символов ответа. Ни API-ключ, ни заголовок `Authorization` журнал никогда не показывает.

## Проверка и troubleshooting

```bash
go test ./...
go vet ./...
```

- **«API-ключ не настроен»** — создайте `.env` по шаблону `.env.example` и укажите в нём `DEEPSEEK_API_KEY`, либо задайте непустую переменную окружения, затем перезапустите `go run .`.
- **«DeepSeek не принял API-ключ»** — проверьте ключ в кабинете DeepSeek, затем экспортируйте его заново и перезапустите сервер.
- **«Не удалось получить ответ»** — проверьте интернет, баланс/лимиты DeepSeek и повторите запрос.
- **Страница не открывается** — убедитесь, что в Terminal написано `listening on http://localhost:8080`, затем откройте именно этот адрес.

## Безопасность

`.gitignore` исключает `.env` и другие локальные файлы с секретами. Не вставляйте ключ в HTML, JavaScript, README, коммиты, скриншоты или сообщения. Сервер не логирует тело запроса, ключ, содержимое `.env` или заголовок `Authorization`.

## Публикация

Перед публикацией проверьте `git status`, чтобы убедиться, что `.env` отсутствует в списке. Публиковать изменения можно только после отдельного подтверждения владельца проекта.
