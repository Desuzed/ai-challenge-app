# AI Challenge App

Локальное веб-приложение для работы с языковыми моделями и ассистентом разработчика. Go-сервер объединяет диалог, параметры генерации, память, поиск по документации (RAG) и инструменты MCP. Браузер показывает ответы, источники и технический журнал.

## Возможности

- Основной чат с DeepSeek, локальной Ollama и отдельным сервером Ollama.
- Сохранение истории в `.local/agent-history.json`, профили и отдельные слои памяти.
- Стратегии контекста Sliding Window, Facts и Branching.
- Поиск по README, всей документации `docs` и выбранным Go-исходникам.
- Проверка точных цитат и явный отказ при отсутствии документального ответа.
- MCP для локального проекта, GitHub, Яндекс Диска, погоды и новостей.
- `/help <вопрос>`: ответ о проекте по документации.
- `/diff`: текущая локальная git-ветка через MCP без генерации ответа.
- Планировщик задачи с явными переходами, паузой и возобновлением.
- Отдельные режимы сравнения формата ответа, рассуждений и параметров генерации.

## Быстрый запуск

Требуется Go 1.25 или новее. Из корня проекта:

```sh
cp .env.example .env
chmod 600 .env
# Заполните DEEPSEEK_API_KEY в .env для ответов через DeepSeek.
go run .
```

Откройте <http://localhost:8080>. Сервер слушает только `127.0.0.1`; другой порт задаётся переменной `PORT`. Остановка — Ctrl+C. Без ключа DeepSeek можно использовать доступные модели Ollama; внешние интеграции настраиваются отдельно.

Непустая переменная окружения процесса имеет приоритет над одноимённой настройкой в `.env`. API-ключ читает Go-сервер и передаёт DeepSeek в HTTP-заголовке `Authorization`; браузер ключ не получает. `.env` исключён из Git.

## Подготовка RAG

Для эмбеддингов используется локальная Ollama с моделью `embeddinggemma`. Модель ответа выбирается отдельно: эмбеддинг и генерация решают разные задачи.

```sh
ollama pull embeddinggemma
go run ./cmd/indexdocs -root .
```

Индексатор включает README, рекурсивно документы из `docs` и выбранные исходники. Он создаёт `.local/rag/index-fixed.json`, `.local/rag/index-structure.json` и `.local/rag/report.json`. Fixed — окна по 1200 Unicode-символов с перекрытием 150; structure — разделы по заголовкам Markdown и объявлениям Go, с дополнительным делением длинного текста. Каждый чанк содержит `source`, `title`, `section`, `chunk_id`, исходный текст и эмбеддинг.

После изменения документов или индексируемого кода пересоберите индекс. Поиск проверяет SHA-256 включённых файлов; устаревшие данные отклоняются. После добавления новых документов также нужен запуск индексатора.

## Помощь по проекту

В основном чате:

```text
/help
/help расскажи о проекте
/help Как устроены каталоги internal, cmd и static?
/help Как подключены MCP-серверы?
/help Где хранится история диалога?
/diff
```

`/help <вопрос>` отвечает на вопрос о проекте только в рамках этого вызова. Например: `/help Где хранится история?`. `/help` без вопроса показывает инструкцию без запроса к языковой модели. `/structure` задаёт готовый вопрос о структуре проекта. Следующие обычные сообщения обрабатываются как обычный чат; помощь не включает сохраняемый режим.

Для `/help <вопрос>` и `/structure` сервер включает RAG независимо от переключателя и проверяет цитаты модели. Git-инструменты эти команды не вызывают и текущую ветку к ответу не добавляют. Общий вопрос «расскажи о проекте» использует вводные разделы индексированного README; конкретные вопросы проходят обычный поиск. Контекст помощи сфокусирован на текущем вопросе; старые ошибки команд не используются как образцы ответа. Модель, профиль и правила пользователя сохраняются. При лимите до 768 токенов запрашивается одно короткое утверждение с цитатой. При ошибке JSON/цитат допускается одна повторная генерация; разные причины отказа показаны отдельно. В основном чате запрос DeepSeek ограничен 60 секундами вместе с поиском и повторной генерацией.

`/diff` без аргументов показывает текущую git-ветку через Project MCP. Команда работает без RAG и генеративной модели; на паузе задачи вызов инструмента пропускается.

`/reindex` действительно перечитывает README, docs и выбранные исходники, строит fixed/structure и сохраняет оба индекса с отчётом. Ответ появляется после окончания операции и содержит фактическое число файлов и фрагментов. Неизвестные команды не передаются модели.


## Структура проекта

Каталог `internal/` содержит backend: агента, HTTP-обработчики, модели данных, клиентов LLM, RAG и MCP. Каталог `cmd/` содержит отдельные команды индексации и проверки RAG. Каталог `static/` содержит браузерный интерфейс: HTML, CSS и JavaScript. В `main.go` эти компоненты соединяются и запускается сервер. В `docs/` находится документация приложения, в `scripts/` — диагностические скрипты.

### Карта компонентов

| Путь | Назначение |
|---|---|
| `main.go` | Запуск HTTP-сервера, конфигурация, маршруты, соединение RAG и MCP |
| `internal/agent/` | Диалог, память, профили, `/help`, планировщик, проверка цитат |
| `internal/handlers/` | HTTP-обработчики, проверка JSON, сессии и ошибки |
| `internal/models/` | Общие структуры запросов, ответов и состояния |
| `internal/llmrouter/` | Выбор провайдера по идентификатору модели |
| `internal/deepseek/`, `internal/ollama/`, `internal/openrouter/` | Клиенты провайдеров |
| `internal/ragindex/` | Загрузка корпуса, чанки, эмбеддинги, сохранение индекса |
| `internal/rag/` | Векторный и лексический поиск, фильтрация и ранжирование |
| `internal/projectmcp/` | MCP текущей локальной git-ветки |
| `internal/mcpbridge/` | Яндекс Диск и общий каталог MCP |
| `internal/githubmcp/`, `internal/weathermcp/`, `internal/newsmcp/` | Остальные MCP-серверы |
| `cmd/` | Индексация и воспроизводимые проверки RAG |
| `static/` | HTML, CSS и JavaScript интерфейса |
| `scripts/` | Диагностика Ollama и сравнение параметров моделей |
| `docs/` | Документация приложения и его API |
| `.local/` | Локальные индексы, состояние и отчёты; не включается в Git |

Основной путь запроса: браузер → `POST /api/agent/chat` → обработчик → агент → RAG и/или MCP → выбранная модель → проверка ответа → сохранение истории → браузер. MCP-серверы и клиенты соединены через in-memory transport официального Go SDK; отдельный процесс MCP для этой схемы не требуется.

## Проверка изменений

```sh
go test ./...
go vet ./...
node --check static/app.js
git diff --check
```

Автотесты используют временные данные и подставные провайдеры. Для проверки настоящих эмбеддингов и ответов модели используйте процедуры из [docs/testing.md](docs/testing.md). Наличие теста или документа не означает, что внешний сервис сейчас доступен.
